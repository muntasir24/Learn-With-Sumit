# 2.1 Responding to Events - Adding Event Handlers

### 2.1.0 Passing vs. Calling Functions in Event Handlers

When adding event handlers in React, there is a fundamental rule: **You must pass the function, not call it.** 

The difference might look like just a pair of parentheses `()`, but it completely changes how and when your code runs.

#### 1. Using Named Functions

- **Correct (Passing):** `<button onClick={handleClick}>`
  - You are giving React the *reference* to the `handleClick` function. React will save it and **only** call it when the user actually clicks the button.
- **Incorrect (Calling):** `<button onClick={handleClick()}>`
  - The `()` at the end tells JavaScript to execute the function **immediately** during the component's render phase. It will fire before the user even sees the button, and clicking the button later will do nothing.

#### 2. Using Inline Functions

This same logic applies when you write functions inline (directly inside the JSX).

- **Correct (Passing an anonymous function):** `<button onClick={() => alert('Clicked!')}>`
  - You are creating an anonymous arrow function `() => ...` and passing it to React. It waits patiently for the click.
- **Incorrect (Calling immediately):** `<button onClick={alert('Clicked!')}>`
  - The `alert()` executes instantly when the component parses the JSX.

#### 💡 The Golden Rule
Whenever you see `onClick={...}`, what is inside the curly braces `{}` **must be a function definition or a variable pointing to a function**.

### 2.1.1 Forwarding Props with JSX Spread Syntax

Sometimes a component receives a lot of `props` but doesn't actually use them itself. Instead, it just "passes them down" (forwards them) to another child component. 

Writing out every single prop manually can get very repetitive.

**Repetitive Way (Explicitly listing props):**
```jsx
function Profile({ person, size, isSepia, thickBorder }) {
  return (
    <div className="card">
      <Avatar
        person={person}
        size={size}
        isSepia={isSepia}
        thickBorder={thickBorder}
      />
    </div>
  );
}
```

**Concise Way (Using Spread `...` syntax):**
```jsx
function Profile(props) {
  return (
    <div className="card">
      <Avatar {...props} />
    </div>
  );
}
```

#### ⚠️ Keep in mind:
- The `...props` syntax takes all properties inside the `props` object and automatically passes them to `<Avatar />`.
- **Use with restraint:** Only do this when it makes sense (like a simple wrapper component). If you use it everywhere, it gets hard to track what data a component is actually receiving!

### 2.1.2 Passing JSX as `children`

In plain HTML, we nest tags inside each other all the time:
```html
<div>
  <h2>Title</h2>
  <img />
</div>
```

You can do the **exact same thing** with your own React components! 

#### 💡 The "Hole" Analogy (Very Important!)
When you create a generic wrapper component (like a `Card`, `Modal`, or `Alert`), it doesn't need to know what goes inside it. It's just a visual box.

Think of it like a **picture frame**. The frame provides the border and style, but it leaves a big empty **hole** in the middle for you to put a picture in.

In React, that "hole" is a special prop called **`children`**. Whatever you put between the opening and closing tags of the component will automatically be passed into the `children` prop.

#### Example 1: A Layout Card
**Step 1: The Wrapper Component (The Picture Frame)**
```jsx
// We destructure { children } from props
function Card({ children }) {
  return (
    <div className="card-styling">
      {/* This is the "hole". Whatever is passed inside <Card> will appear here! */}
      {children}
    </div>
  );
}
```

**Step 2: The Parent Component (Putting a picture in the frame)**
```jsx
export default function Profile() {
  return (
    <Card>
      {/* Everything here becomes the "children" */}
      <h1 className="name">Katsuko Saruhashi</h1>
      <Avatar size={100} />
    </Card>
  );
}
```

#### Example 2: A Reusable Alert Box
Let's look at another common use case. Building an `AlertBox` that can show anything!

**The Alert Box Component:**
```jsx
function AlertBox({ children }) {
  return (
    <div className="alert-background bg-yellow-100 border-yellow-500 p-4 rounded">
      <strong>⚠️ Warning!</strong>
      <div className="alert-content mt-2">
        {/* The "hole" for the warning message */}
        {children}
      </div>
    </div>
  );
}
```

**Using the Alert Box:**
You can fill the "hole" (`children`) with just text:
```jsx
<AlertBox>
  Your password is too weak!
</AlertBox>
```

Or you can fill it with lots of complex HTML and other components:
```jsx
<AlertBox>
  <p>Are you sure you want to delete this file?</p>
  <button>Yes, Delete</button>
  <button>Cancel</button>
</AlertBox>
```

As you can see, `AlertBox` doesn’t care *what* is inside. It just takes whatever you give it and places it precisely where `{children}` is located.
